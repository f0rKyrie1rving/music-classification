# 应用 v1.1：已经接入的概率改进

本文保留 v1.1 接入时的历史记录。当前桌面入口已改用 [v1.2 固定候选](APPLICATION_V1_2.md)；
`predict_app.py` 和原有模型继续作为 v1.1 对照，以下历史实验结果不变。

这版直接修改应用的输出方式：修正偏高的氛围音乐分数，同时保持原来的标签判断。
新入口为 `predict_app.py`，桌面程序默认使用它，版本号为 **1.1.0**。
旧模型文件、旧 `predict_maest.py`、旧评估结果均保留。

**后续新歌验收更新：** 204 首新歌、150 位艺人的概率误差仅下降 **0.67%**，
不确定区间跨零，未达到预先规定的通过标准。这版应保留实验性定位，不能把下文旧样本
上约 6% 的收益作为对新歌的保证。详见[完整新歌验收](application_fresh_validation/SUMMARY_ZH.md)。

## 你能看到什么变化？

- 表格默认显示修正后的估计值和对应门槛。
- 勾选 **Compare original scores**，可以立即查看原始分数，不必重新分析音频。
- CLI 使用 `--raw-scores` 可以恢复旧分数和旧门槛。

附带的示例音频经过真实 CPU 推理：氛围音乐的显示分数从 **0.0301** 变为 **0.0078**，
门槛从 **0.3750** 同步变为 **0.1321**，最终标签仍为 **rock**。
这个例子用于说明界面变化，不是判断模型优劣的单个成功案例。

## 实际改善了多少？

这次评估使用应用真正加载的最终模型。它用 1,206 首开发歌曲训练，
不同于此前用较少歌曲拟合的研究模型；没有直接套用研究模型的校准参数。

| 已有评估歌曲 | 原始平均概率误差 | v1.1 平均概率误差 | 相对下降 |
| --- | ---: | ---: | ---: |
| 239 首历史歌曲，89 位艺人 | 0.127350 | 0.119549 | 6.13% |
| 266 首回顾性歌曲，200 位艺人 | 0.133977 | 0.125173 | 6.57% |

误差指四个标签平均的 Brier 分数，越小越好。另一项概率评分 log loss 也下降：
239 首从 **0.395202** 到 **0.373046**；266 首从 **0.418588** 到 **0.399780**。

**505 首歌、两种判断策略下，标签判断变化都是 0。** 因而这些样本上的准确性、
召回和误报计数没有因修正而改变。这一版改善的是概率数字，不是声称识别准确率
提高了 6%。每个标签内部的分数排序保持单调，不同标签之间的分数高低关系可能改变。

两批歌曲都已经在项目中使用过，这些是回顾性结果。按艺人重采样 2,000 次，
四标签平均 Brier 的“新版减旧版”95% 区间为：

- 239 首：**[−0.022406, +0.010388]**，跨过零，不能据此声称稳定显著改善。
- 266 首：**[−0.015414, −0.002232]**，在这一条件性计算中支持改善方向。

区间固定了当前模型和修正规则，没有包括重新训练、选方法或多重比较的不确定性。
历史样本中的观察不保证所有用户音乐都有相同收益，也没有修复数据标签不完整的问题。

## 怎么改的，为什么不影响标签？

原应用只对氛围音乐使用了类别平衡权重。训练集该标签有 **244 首阳性、962 首阴性**。
新版本对该标签的 log-odds 加上 `log(244/962) = −1.3718462253725046`，其他三类不变。
这是一项根据训练计数确定的固定修正，不需要再用评分歌曲学习参数。
在有正则化和有限数据时，它不是“重新训练一个无权重模型”的精确替代。

显示门槛使用相同变换，标签仍按原始未四舍五入的分数判断，避免边界翻转。
原 selective 策略中用于关闭标签的 **1.01** 门槛保持原样。产物有固定 SHA-256，
并绑定原模型权重、元数据、训练计划、训练 ID 顺序和训练数据标识。

这类权重修正是已有方法的应用，参见
[Caplin、Martin 与 Marx（2022）](https://arxiv.org/abs/2205.04613)，不作为新算法宣传。

## 怎么运行？

在原项目目录、现有环境中运行桌面入口：

```sh
.venv-improve/bin/python desktop_app.py
```

命令行分析或比较原始分数：

```sh
.venv-improve/bin/python predict_app.py data/previews/track_0207501_30s.wav
.venv-improve/bin/python predict_app.py data/previews/track_0207501_30s.wav --raw-scores
```

新用户的依赖安装步骤见[README](../README.md)。Windows 打包规则已包含新模块和
修正文件，并检查安装包实际使用修正入口；本轮在 macOS 上完成源码测试，
**没有生成或发布新的 Windows `.exe`**。完整安装/卸载验证需要后续在 Windows 构建任务运行。

## 验证与复现

79 项项目测试通过。真实示例音频的桌面推理路径通过，输出为 v1.1、修正模式和 rock 标签。
独立检查还逐项比较实际 505 首歌曲的新旧接口、分数公式、两种策略及边界行为。
历史 239 首原始分数与存档 float32 值最大差约 **1.13×10⁻⁷**；原始接口返回值则严格一致。
桌面切换逻辑已有程序测试，真实 Windows 图形界面与安装包尚未在本轮运行。

另有一项既有复现问题：旧 `evaluate_release.py` 的历史文件校验会在
`requirements-demo.txt` 停止，因为先前 Windows 提交 `fa09b95` 增加了 `certifi`
依赖，旧校验清单没有更新。这不是本轮引入的变化；本轮没有修改任何清单中的文件。
下面的 v1.1 数值复播使用独立入口，已经通过。

公开的逐曲数值、全部指标和条件性区间在
[application_score_correction.json](../data/evaluation/application_score_correction.json)。
不需要音频或本地特征缓存即可复播数值验证：

```sh
.venv-improve/bin/python evaluate_application_correction.py verify-public
```

从既有缓存重新运行时，使用新的输出目录：

```sh
.venv-improve/bin/python evaluate_application_correction.py freeze --out outputs/application_correction/reproduction_01
.venv-improve/bin/python evaluate_application_correction.py evaluate --out outputs/application_correction/reproduction_01
```

执行规则见[应用修正协议](../experiments/APPLICATION_CORRECTION_PROTOCOL.md)。这次的改动仅用于
应用升级；独立研究仓库的整理和期刊投稿不属于这版发布内容。
